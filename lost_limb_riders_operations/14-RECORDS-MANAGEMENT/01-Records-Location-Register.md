## **1. Purpose**

This register states **where completed records actually belong**. This repository is public: it holds templates, policies, and blank forms. It never holds completed confidential records.

## **2. Confidentiality Architecture**

### Public repository content (this GitHub repository) — allowed

Policies, procedures, blank forms, templates, checklists, job descriptions, document schemas, compliance instructions, generic examples, and completed non-sensitive registers (e.g., blank asset register).

### Restricted records — NEVER in the public repository

| Category | Examples |
|----------|----------|
| Employee identification | SSN, driver's license, passport, date of birth |
| Tax / payroll | Completed W-4, W-2 data, bank account/routing numbers, payroll registers with names+pay |
| Immigration | Completed I-9 and accompanying documents |
| Medical | HIPAA-protected information, accommodations/medical files, workers' comp medical records |
| Personnel | Performance reviews with ratings, disciplinary records, private personnel notes |
| Donor/participant | Confidential donor contact+amount data, participant medical/functional information |
| Authentication | Passwords, credentials, keys, tokens |
| Contracts | Agreements subject to confidentiality clauses |
| Financial accounts | Bank statements, account numbers, card numbers |

If a file would contain any item above, the file is created and stored in the restricted location below — never committed here.

## **3. Records Location Register**

| Record Class | Primary Location | Backup | Custodian |
|--------------|------------------|--------|-----------|
| Corporate records (articles, bylaws, minutes) | Corporate records binder + encrypted digital | Secure cloud storage | Secretary |
| IRS file (determination, 990s) | IRS file binder + encrypted digital | Secure cloud storage | Treasurer/Secretary |
| Finance (ledger, bank, reconciliations) | Secure filing + accounting software | Encrypted backup | Finance Director |
| Payroll records | Payroll provider system + secure filing | Encrypted backup | Bookkeeper/Payroll |
| I-9 file | Separate restricted file | Per USCIS rules | HR |
| Personnel files | Locked filing + restricted digital | Encrypted backup | Executive Director/HR |
| Medical/accommodation files | Separate locked filing | Encrypted backup, restricted | Executive Director |
| Donor records | CRM + restricted filing | Encrypted backup | Donor Relations Manager |
| Grant files | Secure filing + grant folder | Encrypted backup | Grant Writer |
| Contracts | Contracts binder + encrypted digital | Secure cloud storage | Administration |
| Event files | Event records filing | Encrypted backup | Events Director |
| Incident/insurance files | Restricted filing | Encrypted backup | Insurance & Risk Manager |
| Volunteer files | Volunteer Coordinator filing | Encrypted backup | Volunteer Coordinator |
| Compliance filings | Compliance file + agency portals | Encrypted backup | Records & Compliance Officer |

**Standards:** restricted records use locked physical storage or encrypted digital storage with access controls and regular encrypted backups. Approved providers (accounting, payroll, CRM) are selected by the Board and reviewed annually.

## **4. What to Do When Unsure**

If unsure whether a record is public or restricted, treat it as **restricted**. Ask the Records & Compliance Officer. Never commit restricted data to the repository on the assumption that "it's just a test file."

## **5. Review**

Reviewed annually and whenever storage or systems change.
