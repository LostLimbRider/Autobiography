## **1. Purpose**

This document is both a **form** for post-event lessons learned and a **worked example** using a de-identified reconstruction of an actual organizational experience: a downtown Fort Dodge concert event. It exists to prove the transactional system would catch the failure that the event exposed.

## **2. The Test Case — Reconstructed Generically**

> **Scenario:** A community organizer asked Lost Limb Riders to staff a downtown Fort Dodge concert. The organization agreed verbally. Lost Limb Riders committed workers — riders, volunteers, and staff — to a multi-hour shift. The event involved labor, attendance, and a promise of compensation or donation from the organizer. After the event, questions arose: who authorized this? What was promised? How many hours were worked? What was each worker owed? Was labor funded? Were there any records?

No personal or confidential information is included. The event is reconstructed at the transaction level so the organization can verify the new system would have prevented the outcome.

## **3. Questions the New System Must Answer — With Answers**

| Question | Where the system answers it |
|----------|-----------------------------|
| Who authorized the event? | EVT-AUTH-001 (authorization signature + approval) |
| What was the organization promised? | Written contract (CTR-002) or event authorization financial terms |
| What did the organization expect to receive? | EVT-FIN-001 projected revenue line |
| How many workers were needed? | EVT-HR-001 staffing plan |
| How many hours were required? | EVT-HR-001 scheduled hours; HR-TIME-001 actual hours |
| What should each worker have been paid? | Approved rates (HR-COMP-001 / payroll records) |
| What did labor actually cost? | EVT-CLOSE-001 labor reconciliation |
| What other expenses occurred? | EVT-CLOSE-001 expense reconciliation (FIN-EXP-001) |
| Was the event profitable? | EVT-CLOSE-001 final result calculation |
| Was labor adequately funded? | EVT-FIN-001 labor funding flag |
| What documentation existed? | Event file (EVT-MSTR-001 cross-references) |
| What documentation was missing? | EVT-CLOSE-001 outstanding items |
| How would the new system catch the problem beforehand? | EVT-FIN-001 flags — see section 5 below |

## **4. What Was Missing (based on the reconstructed scenario)**

- **Written authorization** — no EVT-AUTH-001 existed; acceptance was verbal.
- **Financial feasibility** — no projected revenue/labor comparison; labor was committed with no confirmed funding.
- **Written contract** — no defined scope, payment, or terms.
- **Staffing plan** — worker count and hours were not planned or documented up front.
- **Time records** — actual hours worked were not captured at the time.
- **Rate documentation** — no approved rates existed for the work performed.
- **Expense log** — out-of-pocket costs were not tracked.

The result was an event whose economics could not be verified and whose labor obligations were unclear.

## **5. How the New System Would Have Prevented This**

| New-system step | Prevention |
|-----------------|-----------|
| **EVT-MSTR-001** — Event ID assigned at first request | The event would have existed as a tracked transaction, not a memory |
| **EVT-AUTH-001** — authorization before acceptance | Verbal commitment would have triggered a documented authorization decision |
| **EVT-FIN-001** — feasibility before accepting | Labor funding flag would have shown labor exceeded funded revenue **before** workers were committed; the organizer would have been asked to fund it or the organization would have declined or negotiated |
| **CTR-002 contract** | The promise (fee, hours, payment terms) would be in writing |
| **EVT-HR-001** — staffing plan | Worker count and hours set and funded in advance |
| **HR-TIME-001** — time records | Actual hours captured, certified, and approved |
| **EVT-CLOSE-001** — closeout | Financial result calculated; variance documented |

**Core lesson:** The organization must know the economics before accepting an assignment, and no promise is accepted without documentation. Under the new system, an unfunded, undocumented, labor-heavy event is flagged at the feasibility step — before any worker is scheduled.
